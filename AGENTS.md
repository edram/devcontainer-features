# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this repo is

A collection of [Dev Container Features](https://containers.dev/implementors/features/) published to GHCR. Currently one feature: `claude-code`, which installs the Claude Code CLI. Layout follows the official [`devcontainers/features`](https://github.com/devcontainers/features) repo conventions.

```
src/<feature-id>/devcontainer-feature.json   # metadata + options (id MUST equal the folder name)
src/<feature-id>/install.sh                  # runs as ROOT at image-build time
src/<feature-id>/README.md                   # AUTO-GENERATED — do not hand-edit
test/<feature-id>/test.sh                    # runs in the built container as the remote user
```

## Commands

```bash
# Run the feature test locally (needs Docker; pulls the base image — slow, can exceed 9 min)
devcontainer features test --features claude-code --base-image mcr.microsoft.com/devcontainers/base:ubuntu .

# devcontainer CLI is not preinstalled here:
npm install -g @devcontainers/cli

# Quick sanity check on the install script without Docker
bash -n src/claude-code/install.sh
```

There is no build/lint step — features are shell + JSON.

## Publishing & versioning (the main release gotcha)

- `.github/workflows/release.yaml` publishes to GHCR on push to `main` via `devcontainers/action@v1`.
- **Exact semver versions in the registry are immutable.** The action does `Fetching published versions...` and **skips** any version that already exists. If you change a feature but leave `version` unchanged, the release is silently skipped (logs: `Version X already exists, skipping`).
- **Every publishable change must bump `version` in `devcontainer-feature.json`** (semver: patch=fix, minor=feature/option, major=breaking). The floating tags `1` / `1.0` / `latest` auto-update to the newest.
- One-time setup the workflows depend on:
  - Repo Settings → Actions → Workflow permissions → **Read and write**.
  - First published package must be set to **Public** under Packages.
  - A repo secret named **`PAT`** (contents+PR write) for `update-documentation.yml`, so its auto-PR can trigger CI (the default `GITHUB_TOKEN` cannot).

## Workflows

- `release.yaml` — minimal publish-only, mirrors official upstream.
- `test.yaml` — runs `test.sh` on PR/push. Uses `continue-on-error: true` like upstream, so a red test still shows the job green; **check the step logs, not just the job status**.
- `update-documentation.yml` — regenerates `src/*/README.md` from feature metadata and opens an automated PR (commit message tagged `[skip ci]`).

## Notes

- `README.md` for a feature is generated by the action's `generate-docs`; edit `devcontainer-feature.json` (and a `NOTES.md` if added), not the README directly.
